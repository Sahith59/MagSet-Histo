## What the mixture means

For each matched case and magnification subset, let A and K be the accepted component distributions in canonical order `[benign, DC, LC, MC, PC]`. The ensemble is `P = .5*A + .5*K`. Direct-five predicts `argmax(P)`. Two-step sums malignant mass `R = sum(P[1:])`; R below .5 stops as benign, and R at or above .5 selects the largest conditional malignant probability. This is a valid distribution over the same five labels. It is not averaging two hard decisions or training a new subtype representation.

The joint distribution must be mixed **before** deriving the conditional expert. A synthetic example used rA=.9, qA=[.60,.38,.01,.01] and rK=.1, qK=[.01,.97,.01,.01]. Correct joint averaging gives `[.5,.2705,.2195,.005,.005]` and selects DC after routing. Averaging q separately would select LC. The revised source follows the former rule. For an exact zero malignant mass caused by numerical underflow, routing remains benign and stable log probabilities define a finite conditional fallback.

Equal probability weight is not equal influence over the final decision. A sharp KDE posterior can outweigh a less confident logistic posterior even if the latter is more accurate, and vice versa. Neither component has been clinically calibrated by this operation. Both use the same frozen encoder/cohort with different readouts, so they are not independent data sources; potential benefit comes from complementary decisions or confidence, which remains to be measured.

There are two limited mathematical guarantees: mixture negative log-likelihood cannot exceed the **average** component negative log-likelihood, and mixture Brier score equals average component Brier score minus one quarter of squared disagreement between their probability vectors. These are not guarantees against the better component and do not guarantee improved accuracy, macro F1 or rare-type recall. Synthetic scalar checks verified the identities, with maximum Brier arithmetic error about 3.3e-16. They are not research-performance measurements.

## Resolved routing-boundary blocker

The first implementation published probabilities by exponentiating stable logaddexp outputs, while its independent replay published the literal linear probability average. At analytical R=.5, floating-point differences around 1e-16 produced different routing labels in **231 of 1,000 synthetic pairs**. The discrepancy was numerically tiny but consequential for the fixed hard gate; it could also make an otherwise correct collector reject a run.

The revised rule is explicit: published probabilities use float64 `.5*saved_probabilities5_A + .5*saved_probabilities5_K`. Both routing and conditional probability decisions use that canonical vector. Stable joint logs are computed separately from the validated saved log probabilities; the producer uses logaddexp, and replay uses independently scaled exponentials. Conditional probabilities come from canonical malignant probabilities divided by canonical R, with the stable-log fallback only when R is zero. No epsilon band, rounding-to-half rule or threshold tuning was added.

After the change, the same **1,000 synthetic boundary pairs had zero routing-score or label disagreement**, with exact probability agreement between paths. A separate underflow fixture with malignant log masses around −1000 to −1300 retained finite joint/conditional logs, normalized fallback probabilities and the correct benign route. Canonical five-way, binary and conditional probability/log checks passed. These checks used no cohort predictions.

## Provenance and selection review

The loader pins the complete accepted public ledgers by byte hash: Midnight `c9fdd487…` and KDE `e6e98fc…`, plus the unchanged base registration `07b14d63…`. It requires the same encoder/cache, manifest/protocol and label order. The Midnight readout is explicitly **case**, not a silently substituted field or LoRA model.

For every original role and both arms, the implementation binds the actual private base `run.json` hash to its accepted public object. It checks the selected index and C/temperature, selected candidate metric-file hash and embedded candidate, and the selected prediction-archive hash. It validates the selected archive against trusted original-eight labels, pooled-five labels, the eight validation identities and all 15 canonical magnification subsets. Both components are reordered through those trusted identity/subset keys before joining; pairing does not rely on coincidental file row order.

All **40 selected input archives / 4,800 records** must pass binding before any new ensemble blend is returned. The audit receipt includes those bindings, and run/collector reloads repeat them. The expected output is **20 validation archives / 2,400 records** across ten paired roles. The collector rejects missing/extra run or prediction matrices and any fitting/model archives. It independently replays literal linear probabilities and the stable-log representation, recomputes metrics and checks byte hashes. No ensemble fitting metric is emitted: KDE leave-case-out and logistic resubstitution fitting diagnostics are incompatible.

This inheritance matters statistically. Each component was already selected on the same reused validation cases: four C candidates and four temperature candidates, or **eight inherited component-selection opportunities per role/arm**, followed by one fixed blend. Zero new optimized coefficients does not erase those choices, and this is not a four-opportunity matched-capacity comparison. The blend itself is proposed after examining previous development outcomes. Its score must remain exploratory development validation, not a fresh confirmation test.

Keep the fixed weight and threshold, all roles/subsets, all negative outcomes and the registered improvement screen. No per-case, per-class, per-magnification or per-arrangement component picking is present in the reviewed source. A gain would support this fixed readout combination on the existing protocol; it would not establish novelty, solve independent rare-case scarcity, recover cropped-away histology or demonstrate clinical generalization. No 94–95% claim follows before—or automatically after—the artifact replay.
