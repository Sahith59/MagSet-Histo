One precision detail must be explicit: the official config uses `pos_embed_rope_dtype="bf16"`. The source computes rotary phases in that dtype and converts query/key values for the rotation. Frozen FP32 parameters without autocast therefore do not imply every internal operation is FP32. Preserve and record this behavior; blanket `.float()` can change buffer arithmetic. ## Benchmark and learned-MIL audit

GenBio's paper reports **86.0** for BreakHis, but this must not be read as five-category case accuracy. THUNDER's overview misleadingly lists eight classes; its [pinned actual configuration](https://github.com/MICS-Lab/thunder/blob/38905bc97f96a855f3346b2a9dc10a7e2e8083e3/src/thunder/config/dataset/break_his.yaml) uses **F/TA/DC/MC only**, with936 training,196 validation and339 test images. Its [split implementation](https://github.com/MICS-Lab/thunder/blob/38905bc97f96a855f3346b2a9dc10a7e2e8083e3/src/thunder/datasets/dataset/break_his.py) uses40× and fixed provider identifiers. **LC and PC are omitted.** The paper's frozen-feature tile benchmark therefore provides no direct evidence for the rare types currently limiting our case classifier.

Learned MIL remains a plausible later intervention because diagnostic fields need not contribute equally. But the [original BreakHis MIL study](https://www.inf.ufpr.br/lesoliveira/download/Spanhol2019.pdf) studies benign/malignant bags; its best nonparametric method outperformed the tested MIL-CNN. It does not establish a five-label95% target. The [2026 graph-transformer author code](https://github.com/zaiedhussein/breakhis-graph-transformer) includes attention/transformer MIL controls and reports an important protocol contrast:97.1% eight-class accuracy for image-wise evaluation versus71.5–76.3% after patient-disjoint patient-level aggregation. These remain author results under another protocol. The [MagViT paper](https://arxiv.org/abs/2608.16959) is also a binary source task. None is a verified ready-made five-category checkpoint for our roles. Existing CNN/LoRA failures do not prove frozen-feature attention MIL will fail, but46 fitting cases and LC2/PC3 favor testing representation transfer before adding learned bag weights.

## Bounded next experiment

Register GenBio alone before cohort extraction. Use its official full-image224 transform and4608 CLS readout, preserving original fields as the sampling units. Freeze the backbone; keep the existing case-balanced common-center KDE, class/case/field density weights, four temperatures`.01/.03/.1/.3`, direct-five/dual controls, whole-query-case-out fitting support and centering, original46/8/28 roles and all15 subsets. Do not simultaneously choose new crops, centering modes, feature concatenations, ensembles or learned MIL. This estimates transfer under a fixed reader package; the official transform and feature definition also change, so it is not a pure architecture-only intervention.

The subsequently registered extraction cap is one four-image technical smoke with repeat/single/fresh strict reload, then four A40 shards at one GPU and at most45minutes each, plus bounded CPU role jobs and a complete collector. Use the fixed batch4/workers0 recipe and let the smoke establish memory/throughput. Three production GPU-hours is a cap, not a measured prediction. All7,909 fields imply23,727 channel-backbone examples, and raw FP32 features occupy about139MiB. Four magnifications do not create additional independent cases. KDE arithmetic scales approximately1.5× with4608 versus3072 feature dimensions; actual runtime still needs measurement.

The registered study uses C as the primary frozen KDE reference, with F and P contextual; disclose P's higher-F1/worse-proper-loss tradeoff. A gain would support useful representation transfer; complementary errors would motivate a separately fixed follow-up, not an automatic ensemble. No benchmark headline, larger parameter count or successful technical smoke licenses promising94–95% final accuracy.
